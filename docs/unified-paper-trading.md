# Unified Paper Trading workspace

The unavailable estimate was traced to the old ticket: SecurityPicker selection called `change()` (which clears `quote`) and stored the canonical symbol, but never invoked the quote endpoint. Only the separate form submit called `loadQuote()`. Quantity changes therefore left `total = quote && validQuantity ? quote.price * units : null` at null. This is a frontend request-trigger gap, not evidence of a provider-symbol failure for QQQ. The backend still resolves the canonical symbol through the existing security master/provider mapping. No live AWS/provider diagnosis is claimed.

The UI searches both existing authenticated `GET /api/paper/securities?market=us|korea` endpoints in parallel after the existing 300 ms debounce. The API contract is unchanged. Each query requests at most 30 candidates per market; the client merges, deduplicates by market + canonical symbol, ranks exact ticker / ticker prefix / exact name / name prefix / partial match, then displays at most 20. Unicode NFKC, case and whitespace normalization are applied. Partial search failure is explicitly labeled; an unavailable market does not remove the other market's results. No search request fetches a trade quote.

Explicit security selection selects the security's own USD or KRW book and requests the existing authenticated quote endpoint with its canonical symbol. Previous quote requests are cancelled, including providers that resolve after cancellation. Price, identity, currency and expiry are checked before accepting the response. Server-side provider identity, completed-close validation, quote ownership and expiry remain authoritative and unchanged. Quantity changes calculate the estimate from that quote; they do not contact the provider. Refresh Quote retries the same selected security. No unvalidated price or raw provider exception is displayed.

All / U.S. / Korea filter portfolio presentation only. Both books are loaded for the authenticated owner, with the existing session identity recheck and abort on owner change. No USD/KRW sum or FX conversion is computed. Missing books disable review rather than borrow cash from the other currency. The ticket persists across display-filter changes. Pending orders retain their existing per-user, per-market idempotency keys; a pending request from either book is restored on reload.

The second-pass layout puts the compact title alongside both market statuses, portfolio data/activity in the left column, and a shared search/trade/risk rail on the right. The header and selected-security context share two independent latest-snapshot requests. The original market signal helpers and freshness metadata remain in use.

The performance endpoint contains up to 500 actual recorded account valuations, including repeated visits using the same completed daily close. A curve requires at least two valid distinct timestamps and two distinct equity values. Otherwise the UI explains empty, insufficient or unchanged history and shows available recorded evidence. No synthetic points, historical market overlays, FX totals or risk metrics are introduced.

Deterministic frontend tests exercise merged searches, ranking, duplicates, partial failures, automatic settlement, ticket selection/quantity/review handlers, rapid-selection cancellation, pending-order recovery and quote failures. Backend regression tests exercise both existing search endpoints for both roles and reject a USD quote submitted against the KRW book. These tests use mocked providers, not live Yahoo. Browser screenshots were not captured in the implementation environment; the available Windows browser could not launch through WSL.
