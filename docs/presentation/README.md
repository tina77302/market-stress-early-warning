## 1. 발표의 목적과 이야기

제안 제목은 **「AI 기반 시장 스트레스 조기경보: 모델 검증에서 운영·모의투자 검토까지」**다.

팀원은 전체 시스템의 목적, 데이터, 스트레스 정의, 모델, OOS 검증과 대시보드를 설명한다. 이어 김주미가 WATCH 연구 종료 판단, 실제 생성 기록을 통한 검증 보완, 구현된 수동 모의투자의 규칙·비용·성과 해석 한계를 설명한다.

본문에서 모델 성능 설명을 반복하지 않는다. 김주미는 앞선 결과를 한 문장으로 연결한 뒤 맡은 세부 영역으로 들어간다. 발표 담당 구분을 실제 개발·연구 기여 범위로 해석하거나 확인하지 않은 구현을 개인 성과로 쓰지 않는다.

## 4. 팀원 담당: 전체 시스템 1~5장

### 1장. 연구 질문과 개요

현재 관측 가능한 시장정보로 향후 10거래일 내 프로젝트가 정의한 시장 스트레스 사건을 예측한다. 위험 점수와 원인을 확인하여 추가 리스크 점검에 활용하는 시스템이라고 설명한다.

### 2장. 데이터와 정의

| 구성 | 설명 |
| --- | --- |
| SPY | 주식시장 수익률·하락·변동성 정보 |
| VIX | 옵션시장에 반영된 변동성 정보 |
| Baa 회사채 수익률 − 10년 국채 수익률 | 미국 신용 스트레스 대용지표. HY OAS와 구분 |
| MSI | 기존 rolling Z-score 표준화로 결합한 현재 시장 스트레스 수준 |
| Stress Event | MSI가 그 시점 이전의 과거 분포 90분위 기준 이상인 관측 사건 |
| Target_10D | 다음 1~10거래일 중 Stress Event가 한 번이라도 나타나는지 |

한국 모델의 데이터·성능은 미국과 별도로 표시한다. 기존 모델의 Stress Event 타깃과 WATCH 연구의 D3 급락 기준을 구분한다.

### 3장. 모델과 검증

Logistic을 선형 기준모델, XGBoost를 기존 배포 모델로 소개한다. expanding walk-forward로 시간 순서를 유지하고, 학습 라벨의 미래 구간이 테스트 시작과 겹치지 않도록 10개 관측을 제외한다.

과거 차트는 walk-forward OOS 결과다. 이 설계가 원자료의 당시 발표 지연·개정 이력까지 검증했다는 의미는 아니다.

### 4장. 기존 미국 10D OOS 결과 — 원본 대조 후 확정

| ROC-AUC | 0.9220 | 0.8991 |
| PR-AUC | 0.8065 | 0.7778 |
| Precision | 0.4932 | 0.5929 |
| Recall | 0.8665 | 0.7760 |
| False Alarm Rate | 0.1885 | 0.1128 |

출처: [기준 커밋 README의 10-Day Horizon 표](https://github.com/tina77302/market-stress-early-warning/blob/8d3e75f55d68dacea36925de409553f13157cbb2/README.md). 고정 0.5 임계값, OOS 5,060개 관측, 양성비율 17.47%로 기재된 기존 인용이며 이번 문서 작업에서 재산출하지 않았다. **현재 CSV는 5,057행(2006-08-09~2026-09-16)으로 표본 수가 다르다.** 같은 평가 표본인지 확인되지 않았으므로 표의 수치를 발표 확정값으로 사용하기 전에 원본을 대조한다. 해소 전에는 수치표 대신 검증 방식과 지표별 차이를 설명한다. 자세한 범위는 [근거 점검](implementation-evidence.md)을 따른다.

Logistic은 AUC·Recall, XGBoost는 기준 임계값에서 Precision·오경보 부담에 차이를 보인다. 기존 XGBoost 운영 선택을 유지하되 모든 지표에서 우수하다고 설명하지 않는다. Risk Score를 보정된 사건 확률로 해석하지 않는다.

### 6장. WATCH 검토와 미채택 판단

| 한국 D3의 5일 선행 커버리지 | Z-score WATCH | XGBoost |
| --- | ---: | ---: |
| 사전 경고가 있었던 사례 / 전체 사례 | 6 / 19 (31.6%) | 8 / 19 (42.1%) |

미래정보 누수 없이 구현됐다는 연구 판정과 제품 채택 판단을 구분한다. MSI 기반 사건에서는 좋아 보였으나, 실제 급락 D3 기준에서 추가 효용을 충분히 입증하지 못했다. WATCH 연속 ON 구간 대부분도 5일 내 급락으로 이어지지 않았다.

10/12 첫 급락 때 OFF, 10/13 급락 당일 ON이었다. 이후 10/15 추가 급락 전에 ON이었던 범위로 설명한다. 당시 실제 발행 로그가 없어 **retrospective shadow result**로 표시한다.

이 결과와 판정은 프로젝트 책임자가 2026-10-19 제공·확정한 연구 결론이다. D3 상세 정의·평가기간·에피소드 규칙·대상 지수는 기존 원본에 연결하며 임의로 추정하지 않는다. 새 WATCH 튜닝은 진행하지 않는다.

### 7장. 운영 검증 보완

7개 필수 항목은 생성 시각·관측일·Risk Score·MSI·모델 식별값·입력 식별값·데이터 신선도다. WIP에는 불변 로그, LIVE/RETROSPECTIVE 구분, 스냅샷 게시와 Data Health 코드가 있다. **미구현 전체로 설명하지 않되 실제 운영 검증 완료로도 발표하지 않는다.**

실제 구현의 `generated_at`은 게시 시각이고 추론 시각은 `model_inference_at`이다. `input_snapshot_sha256`은 게시 payload 해시여서 계획의 feature row 해시와 동일하지 않다. 계획의 SHADOW/BACKFILL 개념과 실제 RETROSPECTIVE 유형도 구분한다. 상세 대응은 [근거 점검 6절](implementation-evidence.md#6-live-monitoring-logdata-health의-구현과-남은-확인)에 둔다.

남은 확인은 실제 운영 행, 입력·모델 재현, 재시작 후 보존, 배포 커밋과 게시·전달 증거다. 정답 관측기간이 끝난 후 성능을 평가하며 로그 구현 자체를 prospective OOS 성과로 제시하지 않는다.

### 8장. 모의투자

슬라이드 제목은 **「모의투자 구현과 성과 해석의 한계」**로 고정한다. WIP 코드로 확인한 기능을 설명하고 아직 없는 성과 수치를 보충하지 않는다. 세부 소스는 [근거 점검](implementation-evidence.md)에 고정 커밋 링크로 모았다.

| 설명 항목 | 확인 결과와 발표 내용 |

1:45 구성은 **기능·자금 0:25 → 주문·가격·비용 0:35 → 기록·조건부 분석 0:25 → 미확인 성과 0:20**이다. 본문에는 기능 3개와 한계 3개만 두고 세부 세금·환율표는 부록에 둔다.

시연이 가능하면 통합 잔고 → 종목·수량 선택 → 가격 관측일과 비용/환전 미리보기 → 주문 이력과 성과 이력의 구분을 보여준다. 발표 준비를 위해 새 주문을 넣거나 기존 계정을 초기화하지 않는다. 시연 환경이 WIP를 포함하지 않으면 코드 근거표를 사용하고 실제 화면을 본 것처럼 말하지 않는다.

향후 검증 설계로 동일 자산·기간의 매수보유, 비용 차감 수익률·MDD·위험노출을 비교할 수 있다. 먼저 신호 가용 이후 실행 가능한 가격과 규칙을 고정해야 한다. 현재의 완료 종가 모의 체결만으로 실행 가능한 투자전략의 우위를 입증하지 않는다. 예측 AUC나 조건부 하방 분위수도 그 증거로 쓰지 않는다.

### 9장. 마무리와 완성 순서

Live Monitoring Log 구축·운영 확인, Data Health 표시·검증, 최종 UI 확인, AWS 호환버전 배포, 전체 QA, 발표 정리 순서를 유지한다. WIP 코드 확인과 운영 완료를 구분하고 실제 증거로 상태를 갱신한다. 모의투자 성과를 만들기 위한 새 규칙 탐색이나 새 모델 연구를 추가하지 않는다.
