## 1. 발표의 목적과 이야기

제안 제목은 **「AI 기반 시장 스트레스 조기경보: 모델 검증에서 운영·모의투자 검토까지」**다.

팀원은 전체 시스템의 목적, 데이터, 스트레스 정의, 모델, OOS 검증과 대시보드를 설명한다. 이어 김주미가 기존 경보의 추가 검토에서 확인한 한계, WATCH 연구 종료 판단, 실제 생성 기록을 통한 검증 보완, 모의투자에서 확인할 활용 효과를 설명한다.

본문에서 모델 성능 설명을 반복하지 않는다. 김주미는 앞선 결과를 한 문장으로 연결한 뒤 맡은 세부 영역으로 들어간다. 발표 담당 구분을 실제 개발·연구 기여 범위로 해석하거나 확인하지 않은 구현을 개인 성과로 쓰지 않는다.

## 4. 팀원 담당: 전체 시스템 1~5장

### 1장. 연구 질문과 개요

현재 관측 가능한 시장정보로 향후 10거래일 내 프로젝트가 정의한 시장 스트레스 사건을 예측한다. 위험 점수와 원인을 확인하여 추가 리스크 점검에 활용하는 시스템이라고 설명한다.

### 2장. 데이터와 정의

| 구성 | 설명 |
| --- | --- |
| SPY | 주식시장 수익률·하락·변동성 정보 |
| VIX | 옵션시장에 반영된 변동성 정보 |
| Baa 회사채 수익률 − 10년 국채 수익률 | 미국 신용 스트레스 대용지표. HY OAS와 구분 |
| MSI | 기존 rolling Z-score 표준화로 결합한 현재 시장 스트레스 수준 |
| Stress Event | MSI가 그 시점 이전의 과거 분포 90분위 기준 이상인 관측 사건 |
| Target_10D | 다음 1~10거래일 중 Stress Event가 한 번이라도 나타나는지 |

한국 모델의 데이터·성능은 미국과 별도로 표시한다. 기존 모델의 Stress Event 타깃과 WATCH 연구의 D3 급락 기준을 구분한다.

### 3장. 모델과 검증

Logistic을 선형 기준모델, XGBoost를 기존 배포 모델로 소개한다. expanding walk-forward로 시간 순서를 유지하고, 학습 라벨의 미래 구간이 테스트 시작과 겹치지 않도록 10개 관측을 제외한다.

과거 차트는 walk-forward OOS 결과다. 이 설계가 원자료의 당시 발표 지연·개정 이력까지 검증했다는 의미는 아니다.

### 4장. 기존 미국 10D OOS 결과

| 기준 README의 지표 | Logistic | XGBoost |
| --- | ---: | ---: |
| ROC-AUC | 0.9220 | 0.8991 |
| PR-AUC | 0.8065 | 0.7778 |
| Precision | 0.4932 | 0.5929 |
| Recall | 0.8665 | 0.7760 |
| False Alarm Rate | 0.1885 | 0.1128 |

출처: [기준 커밋 README의 10-Day Horizon 표](https://github.com/tina77302/market-stress-early-warning/blob/8d3e75f55d68dacea36925de409553f13157cbb2/README.md). 고정 0.5 임계값, OOS 5,060개 관측, 양성비율 17.47%로 기재된 기존 결과이며 이번 문서 작업에서 재산출하지 않았다. 평가기간은 원본 산출물과 대조해 표기한다.

Logistic은 AUC·Recall, XGBoost는 기준 임계값에서 Precision·오경보 부담에 차이를 보인다. 기존 XGBoost 운영 선택을 유지하되 모든 지표에서 우수하다고 설명하지 않는다. Risk Score를 보정된 사건 확률로 해석하지 않는다.

모의투자 세부 설명은 김주미에게 넘긴다. 별도 Z-score WATCH는 메인 제품 경보로 시연하지 않는다.

## 5. 김주미 담당: WATCH·보완·모의투자 6~9장

발언 초안과 발표 전 확인표는 [김주미 담당 대본](joomee-speaker-notes.md)에 모았다.

### 6장. WATCH 검토와 미채택 판단

| 한국 D3의 5일 선행 커버리지 | Z-score WATCH | XGBoost |
| --- | ---: | ---: |
| 사전 경고가 있었던 사례 / 전체 사례 | 6 / 19 (31.6%) | 8 / 19 (42.1%) |

미래정보 누수 없이 구현됐다는 연구 판정과 제품 채택 판단을 구분한다. MSI 기반 사건에서는 좋아 보였으나, 실제 급락 D3 기준에서 추가 효용을 충분히 입증하지 못했다. WATCH 연속 ON 구간 대부분도 5일 내 급락으로 이어지지 않았다.

10/12 첫 급락 때 OFF, 10/13 급락 당일 ON이었다. 이후 10/15 추가 급락 전에 ON이었던 범위로 설명한다. 당시 실제 발행 로그가 없어 **retrospective shadow result**로 표시한다.

이 결과와 판정은 프로젝트 책임자가 2026-10-19 제공·확정한 연구 결론이다. D3 상세 정의·평가기간·에피소드 규칙·대상 지수는 기존 원본에 연결하며 임의로 추정하지 않는다. 새 WATCH 튜닝은 진행하지 않는다.

### 7장. 운영 검증 보완

실제 생성 시점의 `generated_at`, `observation_date`, `risk_score`, `msi`, `model_hash`, `input_hash`, `data_freshness`를 고정 저장한다.

입력 스냅샷과 모델 산출물을 보존하고 LIVE·SHADOW·BACKFILL을 구분한다. 실제 게시·전송은 `published_at`과 전달 상태로 따로 남긴다. Data Health는 소스별 시점·결측·지연을 보여준다.

로그는 향후 실전 OOS 평가의 증거를 쌓는 장치다. 정답 관측기간이 끝나야 성능을 평가할 수 있으며 구축 자체를 성능 검증 완료로 발표하지 않는다.

### 8장. 모의투자

현재 모의투자 구현과 거래·성과 원본은 확인되지 않았다. 발표 전 다음 항목을 기존 산출물에서 확인한다. 아래 비교 방식과 지표는 검증 설계 제안이며 이미 구현한 규칙·산출한 성과를 뜻하지 않는다.

| 설명 항목 | 발표 전 확인할 내용 |
| --- | --- |
| 구현 범위 | 실제 화면·거래 기록이 있는지, 과거 백테스트인지 실제 시점의 모의투자인지 |
| 대상과 기간 | 시장·대상 자산·실험기간·초기자금·현금 처리 |
| 투자 규칙 | 기존 Risk Score가 어떤 비중·보유·매매 판단에 연결되는지 |
| 실행 시점 | 신호 가용시각, 주문 시각, 실제로 실행 가능한 체결 시점·가격 |
| 비교 기준 | 동일 자산·동일 기간의 매수보유 등 단순 기준전략. 실제 채택 여부 확인 |
| 비용 | 수수료·세금·스프레드·슬리피지의 적용 범위와 가정 |
| 성과 | 비용 차감 수익률·최대낙폭·회전율·위험노출·상승장 기회비용 |
| 한계 | 투자 규칙의 사후 최적화, 적은 관측기간, 거래 체결 가정 |

검증 질문은 **기존 신호를 활용했을 때 비용과 기회비용을 포함해 수익·낙폭·노출이 어떻게 달라지는가**다. 예측 AUC가 높다는 사실만으로 투자성과를 주장하지 않는다.

과거 OOS 신호를 사용하더라도 투자 규칙을 같은 평가기간의 성과를 보며 정했다면 별도의 미사용 기간 검증이 필요하다. 실제 모의투자라면 당시 생성 신호와 모의 주문·체결·잔고를 시간순으로 남긴다.

완료 화면과 검증된 수치가 있으면 그대로 보여준다. 미구현이거나 근거가 부족하면 이 장의 제목을 **「모의투자 적용 설계와 검증 계획」**으로 표시하고 성과를 제시하지 않는다.

### 9장. 마무리와 완성 순서

Live Monitoring Log 구축, Data Health 표시, 최종 UI 확인, AWS 호환버전 배포, 전체 QA, 발표 정리 순서를 유지한다. 모의투자는 현재 구현 범위를 확인해 설명하며 이 기획만으로 새 기능 구축이나 새 모델 연구를 추가하지 않는다.
