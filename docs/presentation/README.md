### 3장. 모델과 검증

Logistic을 선형 기준모델, XGBoost를 기존 배포 모델로 소개한다. expanding walk-forward로 시간 순서를 유지하고, 학습 라벨의 미래 구간이 테스트 시작과 겹치지 않도록 10개 관측을 제외한다.

과거 차트는 walk-forward OOS 결과다. 이 설계가 원자료의 당시 발표 지연·개정 이력까지 검증했다는 의미는 아니다.

### 7장. 운영 검증 보완

7개 필수 항목은 생성 시각·관측일·Risk Score·MSI·모델 식별값·입력 식별값·데이터 신선도다. WIP에는 불변 로그, LIVE/RETROSPECTIVE 구분, 스냅샷 게시와 Data Health 코드가 있다. **미구현 전체로 설명하지 않되 실제 운영 검증 완료로도 발표하지 않는다.**

실제 구현의 `generated_at`은 게시 시각이고 추론 시각은 `model_inference_at`이다. `input_snapshot_sha256`은 게시 payload 해시여서 계획의 feature row 해시와 동일하지 않다. 계획의 SHADOW/BACKFILL 개념과 실제 RETROSPECTIVE 유형도 구분한다. 상세 대응은 [근거 점검 6절](implementation-evidence.md#6-live-monitoring-logdata-health의-구현과-남은-확인)에 둔다.

남은 확인은 실제 운영 행, 입력·모델 재현, 재시작 후 보존, 배포 커밋과 게시·전달 증거다. 정답 관측기간이 끝난 후 성능을 평가하며 로그 구현 자체를 prospective OOS 성과로 제시하지 않는다.

| 수익률 | 시장별 (평가액 − 시작 현금) / 시작 현금. 테스트 계정은 같은 종가 매매로 0%이며 성과가 아님 | 통합 USD 평가액 기준. 실제 수치 확인 필요 |
| 비교전략·MDD | 매수보유 비교·MDD 계산/표시 없음 | 비교 산출물·MDD 계산 미확인. 수치 제시 보류 |
| 조건부 10D 분석 | 화면에서 미제공으로 표시 | 과거 유사 스트레스 이후 보유 노출의 10일 수익률 분포. 실제 성과·MDD와 다름 |

1:45 구성은 **기능·계좌 0:25 → 주문·가격·점검 결과 0:35 → 비용과 버전 차이 0:20 → 성과 한계 0:25**이다. 본문에는 배포판 기능과 한계만 두고 WIP 비용표·조건부 분석은 부록·질의응답으로 돌린다.

시연은 배포 사이트의 QA용 테스트 계정으로 한다. 순서는 시장별 잔고 → 종목·수량 선택 → 확정 종가와 가격 관측 시각 → 주문 확인 → 체결 기록이다. 실사용자 계정에는 주문하거나 초기화하지 않는다. 시연 주문은 끝난 뒤 보유를 정리한다. 비용·환전 미리보기는 배포판에 없으므로 시연하지 않고, WIP 코드로만 설명한다. 견적은 2분 뒤 만료되므로 확인 화면에서 오래 머물지 않는다. 만료 뒤 복구 흐름에는 알려진 결함 P2가 있다.

예비 자료로 `main`의 [한국시장 경보 재현 영상](https://github.com/tina77302/market-stress-early-warning/tree/main/docs/demo)을 쓸 수 있다. 과거 OOS 점수 63.1을 로컬 화면에 주입한 재현이며 당시 발행된 LIVE 경보가 아니다. 거래는 현재 종가 기준이므로 과거 경보일의 백테스트도 아니다. 영상을 틀 경우 이 두 문장을 함께 말한다.

향후 검증 설계로 동일 자산·기간의 매수보유, 비용 차감 수익률·MDD·위험노출을 비교할 수 있다. 먼저 신호 가용 이후 실행 가능한 가격과 규칙을 고정해야 한다. 현재의 완료 종가 모의 체결만으로 실행 가능한 투자전략의 우위를 입증하지 않는다. 예측 AUC나 조건부 하방 분위수도 그 증거로 쓰지 않는다.

### 9장. 마무리와 완성 순서

Live Monitoring Log 구축·운영 확인, Data Health 표시·검증, 최종 UI 확인, AWS 호환버전 배포, 전체 QA, 발표 정리 순서를 유지한다. WIP 코드 확인과 운영 완료를 구분하고 실제 증거로 상태를 갱신한다. 모의투자 성과를 만들기 위한 새 규칙 탐색이나 새 모델 연구를 추가하지 않는다.

## 6. 두 발표자의 설명 경계와 질의응답

| 주제 | 먼저 답할 담당 | 답변 경계 |

발표 담당이 해당 영역을 단독 구현했다는 의미는 아니다. 실제 기여는 확인한 범위로만 설명한다.

기존 XGBoost 점수 구간의 `WATCH`, 별도 Z-score WATCH, MSI, 관측 Stress Event, D3를 혼용하지 않는다. 기존 MSI·입력변수의 Z-score는 유지한다.
