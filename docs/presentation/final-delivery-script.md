# 최종 발표 흐름 — 김주미 담당 약 4분

기준: [2026-10-21 실제 작업 결과](../operations/completion-verification-2026-10-21.md).
팀원: 전체 구조·데이터·모델·검증·대시보드. 김주미: 추가 경보 판단·운영 검증 보완·모의투자와 한계.

## 1. WATCH 연구 판단 (약 1분)

추가 경보가 제품에 필요한지 검토했습니다. 확정된 연구 결과에서 한국 D3 19개 사례의 5일 선행 커버리지는 Z-score WATCH 6개, 기존 XGBoost 8개였습니다. 표본이 작아 알고리즘의 보편적 우열은 말할 수 없지만, 추가 기능으로 채택할 만큼의 효용은 확인하지 못했습니다.

10월 사례도 첫 급락 때는 OFF였고 다음 급락 당일 ON이었습니다. 당시 발행 기록이 없는 사후 재계산 결과이므로 실시간 선행 탐지 성공으로 발표하지 않습니다. 연구는 보존하고 추가 튜닝과 제품 통합은 종료했습니다. 기존 점수 구간 WATCH와 MSI의 Z-score 표준화는 유지합니다.

## 2. 운영 검증 보완 (약 1분)

이제 중요한 것은 그날 실제 어떤 입력과 모델로 어떤 점수를 냈는지 남기는 것입니다. 기존 운영 코드에는 게시 기록을 변경하지 않는 로그와 Data Health가 있습니다. 이번에는 실제 추론 입력과 모델 원본을 해시와 함께 보관하고, 동일 실행 재시도가 중복 기록을 만들지 않도록 보완했습니다.

관측일, 추론 시각, 게시 시각은 서로 다릅니다. 데이터 지연과 모델 경보도 구분합니다. 다만 제한된 로컬 검증을 통과한 상태이며, 이 버전의 AWS 배포와 전체 운영 검증을 완료했다고 말하지 않습니다. 실제 로그와 미래 정답이 쌓여야 prospective 평가가 가능합니다.

## 3. 모의투자 (약 1분 30초)

모의투자는 위험 정보를 확인한 사용자가 주문과 계좌 변화를 체험하는 영역입니다. 경보 자체가 매매 수익을 보장한다는 뜻은 아닙니다. 주문 대상, 시장과 통화, 가격 기준일, 수량, 거래비용과 환전 조건을 확인하는 흐름을 보여드리겠습니다.

시연에서는 실제 배포 화면에 있는 기능만 설명하겠습니다. 최신 소스의 비용·통합 계정 기능과 이전 배포판의 시장별 계정을 섞어 설명하지 않겠습니다. 과거 신호 재생은 실시간 실적과 구별하며, 검증되지 않은 수익률이나 MDD 수치는 제시하지 않습니다.

[시연 30~45초: 로그인 → 시장/종목 선택 → 가격 시점·수량 확인 → 주문 검토 화면. 주문 확정은 미리 준비된 시연 계정에서만 수행. 연결 불가 시 기존 영상임을 밝히고 기록된 영상 사용.]

## 4. 마무리 (약 30초)

이번 프로젝트는 경보를 많이 추가하기보다 검증된 범위와 한계를 명확히 하는 데 초점을 맞췄습니다. Risk Score는 향후 10거래일 Stress Event에 대한 기존 모델의 위험 점수이고, MSI는 현재 스트레스입니다. 점수를 보정된 확률이나 급락 예측 성과로 바꾸어 설명하지 않습니다. 남은 과제는 고정 버전의 배포와 실제 기록에 기반한 운영 검증입니다.
