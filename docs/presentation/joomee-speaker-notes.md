# 김주미 담당 발표: WATCH 검토·운영 보완·모의투자

- 기준일: 2026-10-19 (Asia/Seoul)
- 발표 순서: 팀원의 전체 시스템 발표 다음, 본문 6~9장
- 시간안: **4분**. 전체는 팀원 6분 + 김주미 4분이다. 리허설 전 배정안이다.
- 관련 문서: [전체 발표안](README.md), [코드·산출물 근거 점검](implementation-evidence.md), [연구 종료 결정](../decisions/zscore-watch-research-closeout-2026-10-19.md), [제품 완성 계획](../operations/project-completion-plan.md)
- 구현 근거: 원격 `wip/data-automation`의 `4a75acd1e1e73e58c9cb600519401a9ca4a22bc1`. 코드·설정·기존 보고서를 대조했으며 현재 문서 브랜치와 다른 구현이다. 실제 계정 성과·운영 배포는 미확인이다.
- 6~9장의 **발언 초안만** 본문 대본이다. 표·근거·질의응답은 부록이며 4분 안에 모두 읽지 않는다.

## 1. 담당 범위와 인계

팀원은 전체 시스템·데이터·모델·검증·대시보드를 1~5장에서 설명한다. 김주미는 WATCH 검토 1:00, 운영 검증 보완 0:45, 모의투자 1:45, 마무리 0:30을 맡는다. 모델 수식과 전체 성능표는 반복하지 않는다. 발표 담당을 실제 단독 구현·연구 기여 전체로 확대하지 않는다.

팀원 인계:

> 이어서 김주미 님이 추가 경보 검토에서 확인한 한계와 운영 검증 보완 방향, 모의투자 영역을 설명하겠습니다.

## 2. 6장: WATCH 추가 검토와 제품 미채택 판단

- 시간: 1:00, 시작 인사 포함
- 화면: 한국 D3 커버리지 비교, 10월 해석, 연구 종료 결정
- 핵심: 구현의 정상 여부와 제품에 추가할 효용을 구분한다.

| 한국 D3 5일 선행 커버리지 | Z-score WATCH | XGBoost |
| --- | ---: | ---: |
| 사전 경고 사례 / 전체 사례 | 6 / 19 (31.6%) | 8 / 19 (42.1%) |

### 발언 초안

이어서 WATCH 검토와 운영 보완, 모의투자를 말씀드리겠습니다. WATCH는 미래정보 누수 없이 구현됐다는 연구 판정을 받았고 MSI 기반 사건에서는 좋아 보였습니다. 그러나 실제 급락 D3 기준에서는 추가 효용이 충분하지 않았습니다. 한국 19개 사례의 5일 선행 커버리지는 WATCH가 6개, 기존 XGBoost가 8개였습니다.

10월 12일 첫 급락 때는 OFF였고, 13일에는 급락 당일 ON이었습니다. 이후 15일 추가 급락 전에도 ON이었지만, 당시 실제 발행 기록은 없습니다. 따라서 사후 재계산한 shadow 결과로 설명해야 합니다. 별도 WATCH는 제품에 추가하지 않고 연구를 종료했습니다.

### 근거와 해석 범위

수치와 구현 판정은 사용자가 2026-10-19 제공·확정한 연구 결론이다. 이번 문서 작업에서 재현·재튜닝하지 않았다. 19개 사례로 통계적 유의성이나 모든 시장의 우열을 주장하지 않는다. WATCH 연속 ON 구간 대부분도 5일 내 급락으로 이어지지 않았다는 확정 결론을 유지하되, 에피소드 원본 표는 확인 필요다.

Stress Event는 기존 MSI 기준 사건이고 D3는 별도 실제 급락 기준이다. D3 이름으로 임계값을 추정하지 않는다. 기존 XGBoost 점수 구간의 WATCH 명칭과 MSI·입력변수의 Z-score는 유지한다. 종료 대상은 **별도 Z-score WATCH**다.

## 3. 7장: 운영 검증에서 보완할 부분

- 시간: 0:45
- 화면: 필수 7개 항목 + “WIP 코드 확인 / 운영 검증 필요”
- 핵심: 그날 실제 생성한 기록과 사후 재계산을 구분한다.

### 발언 초안

다음은 그날 실제로 무엇을 알고 경고했는지 남기는 운영 검증입니다. 생성·관측 시점, 점수와 MSI, 모델·입력 식별값, 신선도가 필요합니다. WIP에는 수정 방지 로그와 실시간·사후 기록 구분, Data Health 코드가 있습니다.

남은 일은 실제 운영 기록, 해시가 가리키는 원본, 재시작 후 보존과 배포 상태를 대조하는 것입니다. 로그가 있다는 것만으로 실전 성능이 검증된 것은 아닙니다. 미래 정답이 쌓인 뒤 당시 기록으로 평가해야 합니다.

### 부록: 계획과 실제 코드의 구분

| 필수 항목 | 확인한 WIP 대응 |
| --- | --- |
| 생성·게시 시각 | `generated_at`은 게시 트랜잭션 시각, 추론은 `model_inference_at` 별도 |
| 시장 관측일 | `observation_date` |
| Risk Score·MSI | `risk_score`, `msi` |
| 모델 식별값 | `model_sha256` |
| 입력 식별값 | `input_snapshot_sha256`은 게시 payload JSON 해시, 원자료 이력 해시는 별도. 계획의 feature row 해시와 같지 않음 |
| 신선도 | 소스별 날짜, `data_status`, `data_freshness_status` |

계획은 7개 항목이며 위 표에서는 점수·MSI를 한 행에 묶었다. 실제 기록 유형은 `LIVE`/`RETROSPECTIVE`다. 계획의 SHADOW/BACKFILL을 그대로 구현한 enum으로 말하지 않는다. Data Health는 CURRENT/DELAYED/STALE/PARTIAL/ERROR를 사용한다. 공개 스냅샷 게시와 외부 전달·사용자 수신도 구분한다. [근거 점검](implementation-evidence.md)의 원본 링크를 따른다.

## 4. 8장: 모의투자 구현과 성과 해석의 한계

- 시간: 1:45
- 화면: 수동 주문·완료 종가·비용·기록 표. 시연 환경 확인 시 잔고→주문 미리보기→이력
- 핵심: 수동 모의투자 구현은 확인했다. 자동 전략 우위·실제 수익률·MDD는 확인 필요다.
- 배분: 기능·자금 0:25 / 주문·가격·비용 0:35 / 기록·조건부 분석 0:25 / 성과 한계 0:20

### 발언 초안

모의투자는 WIP 브랜치에서 구현을 확인했습니다. 사용자가 미국·한국 주식이나 ETF를 직접 선택하고 수량을 정하는 방식입니다. 새 통합 계정은 10만 달러로 시작하고 원화는 0원이며, 두 시장의 현금과 보유 자산을 달러로 합산합니다. Risk Score는 참고 정보이고 자동 매매 규칙은 없습니다.

주문은 이미 완료된 일봉 종가를 기준으로 모의 체결합니다. 실시간 시세나 다음 날 시가 체결이 아닙니다. 가격 관측 시점과 주문 시점을 따로 남기며, 견적과 비용을 검토한 뒤 제출합니다. 한국 기본 수수료와 매도 비용, 필요한 환전의 0.1% 스프레드 등을 반영하지만 슬리피지와 실제 거래비용 전체를 재현하지는 않습니다.

성과는 비용이 반영된 통합 평가액을 초기자금과 비교하고, 실제 평가 시점부터 기록합니다. 별도의 조건부 10일 분석은 비슷한 과거 스트레스 이후 보유 노출의 수익률 분포입니다. 계정에서 실제로 얻은 수익이나 미래 수익 예측과는 구분합니다.

현재 공개 산출물로는 다일 수익률과 최대낙폭, 매수보유 대비 우위를 확인하지 못했습니다. 따라서 성과 수치는 제시하지 않습니다. 이를 평가하려면 신호 이후 실행 가능한 규칙과 비교 조건, 전체 평가 이력을 먼저 확보해야 합니다.

### 부록: 확인한 기능과 남은 증거

| 항목 | 확인한 사실 | 남은 확인 |
| --- | --- | --- |
| 구현 유형 | WIP에 수동 주문·통합 자금·기록 화면/API 존재 | 현재 시연·배포 환경에 포함됐는지 |
| 초기자금·규칙 | 새 계정 USD 100,000·KRW 0, 정수 수량·현금/보유 한도, 평균 취득원가 | 실제 계정 생성일·실험기간·현재 잔고 |
| 가격·시각 | 당일 행 제외 완료 종가, 견적 120초, 가격 관측일과 주문 처리 시각 별도 | 특정 주문과 당시 실제 신호의 직접 연결 증거 |
| 비용 | 한국 수수료 1.5 bps, 미국 수수료 0 및 별도 매도 규제 비용, 한국 거래세 가정, 환전 10 bps | 버전별 시뮬레이션 가정이며 실제 투자자 적용 요율 표가 아님. 추가 슬리피지 미확인 |
| 계정 수익률 | `(USD 평가액 - 초기 기여금) / 초기 기여금 × 100` 계산과 실제 평가 기록 | 다일 원본과 검증된 수익률 숫자 |
| MDD·비교전략 | MDD 계산/표시·자동 전략 대 매수보유 비교 산출물 미확인 | 전체 기간 일별 자산곡선·동일 조건 비교 |
| 조건부 10D | 현재 보유 비중·환율 고정의 과거 유사 스트레스 분포. 표본 부족/미지원 시 보류 | 비공개 원본 없이는 수치 재현 불가. 실제 성과·MDD로 사용 금지 |

세부 비용표·고정 커밋 소스·성과 한계는 [근거 점검](implementation-evidence.md)에 있다. 시연 환경이 다르면 이 사실표를 사용한다. 미확인 화면을 직접 확인한 것처럼 설명하거나 발표 준비를 위해 새 주문·계정 초기화를 하지 않는다.

향후 전략 비교는 동일 자산·기간·초기조건·비용을 고정한 검증 설계다. 같은 평가기간의 수익률을 보며 규칙을 최적화하면 독립 OOS가 아니다. WATCH 튜닝과 새 모델 연구는 재개하지 않는다.

## 5. 9장: 마무리와 남은 작업

- 시간: 0:30
- 화면: 로그 → Data Health → UI → AWS 호환 배포 → QA → 발표

### 발언 초안

별도 WATCH 연구는 종료하고 기존 XGBoost와 MSI 구조를 유지합니다. 로그·Data Health부터 UI·AWS 호환 배포·전체 QA·발표 순으로 완성합니다. WIP 코드 확인을 운영 완료와 구분하고, 경보는 실제 시점의 기록으로, 모의투자 성과는 비용과 낙폭을 포함한 원본으로 검증하겠습니다.

## 6. 예상 질문

| 질문 | 답변 요지 |
| --- | --- |
| WATCH 연구는 실패인가? | 정상 구현한 후보도 제품에 추가할 효용은 부족할 수 있다. 실제 급락 기준의 근거를 남기고 미채택을 결정했다. |
| 10월 급락을 사전에 잡았나? | 첫 급락 때 OFF, 13일 급락 당일 ON이었다. 당시 발행 기록이 없어 retrospective shadow result다. |
| 기존 모델도 바뀌나? | 별도 Z-score WATCH만 미채택이다. XGBoost와 MSI·입력변수는 유지한다. |
| 로그가 있으면 예측력이 좋아지나? | 성능 개선을 보장하지 않는다. 당시 신호를 평가할 증거가 생긴다. 실제 운영 증거는 추가 확인한다. |
| 자동으로 매수·매도하나? | 사용자가 종목·수량·방향을 정한다. 확인한 주문 경로에 점수 기반 자동 진입·청산 규칙은 없다. |
| 어떤 가격으로 체결하나? | 당일을 제외한 완료 일봉 종가다. 가격 관측일과 주문 시각이 달라 실시간 실행 가능한 전략 검증으로 해석하지 않는다. |
| 실제 수익률과 MDD는? | 수익률 계산 기능은 있다. 공개된 다일 원본이 없어 실제 숫자와 MDD·매수보유 우위는 확인 필요다. |
| 조건부 하방 수치가 MDD인가? | 과거 유사 구간의 10일 수익률 분위수다. 계정 자산곡선의 고점 대비 손실인 MDD와 다르다. |
| 과거 OOS 점수면 투자전략도 OOS인가? | 투자 규칙을 같은 구간의 성과를 보고 정했다면 독립 평가가 아니다. 실행 시점·비용·비교 조건도 별도 검증한다. |

데이터·학습·전체 OOS 성능 질문은 팀원의 원본 설명과 연결한다. 전체 성능표는 표본 수 불일치가 있어 원본 확인 전 확정 수치로 사용하지 않는다.
